# Versioning and updates

Use current package-source versions by default. `windows/apps.json` leaves version pins unset. Existing installations are detected and preserved, not silently upgraded. Record observed versions for troubleshooting, but pin only for a concrete compatibility, security, or reproducibility reason and document that reason. Keep security-sensitive auto-updaters, especially Chrome, on their supported update channel rather than pinning them behind security fixes.

**Infisical CLI pin (release note).** The Infisical CLI is intentionally pinned in `tools.yaml` with `version: "0.44.6"`. The LiteLLM gateway launchers accept exactly this CLI version, so a machine setup that follows `tools.yaml` can satisfy the launcher check instead of installing whatever npm's latest happens to be. The pin governs the install spec only: it applies to new installs performed by `just tools-apply` or a manual `npm install -g @infisical/cli@0.44.6`, and an existing installation is still detected and left unchanged. To move the pin, change the `tools.yaml` version and the version string the launchers check in the same change; a guard test fails when the two disagree. This note records the intent at the time of writing and does not claim any host is already running this version.

No setup script should move existing folders, overwrite personal configuration, install Windows containers, or enable a global AI configuration silently.
