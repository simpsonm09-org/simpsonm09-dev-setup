# Versioning and updates

Use current package-source versions by default. `windows/apps.json` leaves version pins unset. Install behavior depends on the package manager: existing installations are detected and preserved by managers with an installed-tool check, while an explicit apply may reinstall or change an npm tool's version. Record observed versions for troubleshooting, but pin only for a concrete compatibility, security, or reproducibility reason and document that reason. Keep security-sensitive auto-updaters, especially Chrome, on their supported update channel rather than pinning them behind security fixes.

**Infisical CLI pin (release note).** The Infisical CLI is intentionally pinned in `tools.yaml` with `version: "0.44.6"`. The LiteLLM gateway launchers accept exactly this CLI version, so a machine setup that follows `tools.yaml` can satisfy the launcher check instead of installing whatever npm's latest happens to be. When an operator explicitly runs `just tools-apply`, the npm installer runs `npm install -g @infisical/cli@0.44.6` when npm is available; otherwise it prints manual-install guidance. It does not check whether Infisical is already installed. npm may therefore reinstall the pinned version or change an existing version, including upgrading or downgrading it. No apply has run as part of this change. To move the pin, change the `tools.yaml` version and the version string the launchers check in the same change; a guard test fails when the two disagree. This note records the intent at the time of writing and does not claim any host is already running this version.

No setup script should move existing folders, overwrite personal configuration, install Windows containers, or enable a global AI configuration silently.
